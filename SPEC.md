# 1. Resumen ejecutivo

La oportunidad principal no es hacer simplemente una web “más linda”, sino transformar `ceramicaptorico.com.ar` en una **herramienta comercial y técnica para vender ladrillos cerámicos en Misiones y el NEA**.

La evidencia pública permite confirmar que Cerámica Puerto Rico opera en Puerto Rico, Misiones, como fabricante de productos cerámicos; su presencia oficial en Instagram la define específicamente como **“Fábrica de ladrillos cerámicos huecos”** y afirma actividad **desde 1975**.

Fuente:

- https://www.instagram.com/ceramicapuertoricosrl/reels/

La ficha comercial pública ubica la planta en Sección 1°, Colonia San Alberto, Lote 25B, Puerto Rico, Misiones, y publica el teléfono +54 3743 476985.

Hay además evidencia de expansión comercial: en 2023 la empresa anunció un **nuevo corralón en Puerto Iguazú** y publicó como contacto el 3757-310501. Conviene confirmar que esa sucursal y ese número sigan vigentes antes de incorporarlos a la nueva web.

Fuente:

# 3. Historia: punto a validar

La comunicación comercial indica actividad **desde 1975**.

Una publicación societaria de 2017 parece ubicar la inscripción de la persona jurídica actual bastante después.

Esto no implica necesariamente una contradicción. Puede ocurrir que:

- la fábrica tenga actividad desde 1975;
- el emprendimiento haya comenzado con otra figura jurídica;
- la SRL actual haya sido constituida posteriormente;
- haya existido continuidad familiar o comercial.

## Recomendación

Antes de publicar la página “Empresa”, pedir una cronología mínima:

- año de inicio;
- fundadores;
- primeras instalaciones;
- ampliaciones;
- cambios societarios;
- incorporación de hornos o líneas productivas;
- expansión geográfica;
- apertura de sucursales;
- hitos relevantes.

Con eso se puede construir una línea temporal real y fuerte.

# 31. Stack técnico recomendado

## Decisión

### Astro + HTML estático + CSS + JavaScript + PHP mínimo

Para este proyecto, y especialmente en **hosting compartido**, es la opción recomendada.

Arquitectura:

```text
Astro
├── HTML estático
├── CSS
├── JavaScript mínimo
├── componentes Astro
├── opcional: pequeños componentes Vue
└── PHP solamente para endpoints dinámicos
```

Al compilar:

```bash
npm run build
```

Astro genera:

```text
dist/
```

Esa carpeta puede subirse directamente al `public_html`, `www` o equivalente del hosting compartido.

El servidor final no necesita:

- Node.js;
- npm;
- Docker;
- procesos permanentes;
- PM2;
- SSH;
- SSR.

# 32. Por qué Astro

## 1. Excelente para SEO

La salida final es HTML real.

Google no necesita ejecutar una SPA completa para entender:

- productos;
- títulos;
- textos;
- fichas técnicas;
- preguntas frecuentes.

---

## 2. Muy rápido

Astro envía JavaScript solamente cuando hace falta.

Una página de producto puede ser prácticamente:

```text
HTML
CSS
imagen
```

Esto favorece:

- Core Web Vitals;
- SEO;
- conexiones móviles;
- velocidad percibida.

---

## 3. Compatible con hosting compartido

Se desarrolla localmente.

Se compila localmente.

Se publica sólo `dist/`.

El servidor no sabe ni necesita saber que la web fue hecha con Astro.

---

## 4. Permite Vue cuando realmente sirve

Ejemplo:

```astro
<ProductCalculator client:visible />
```

Se puede utilizar Vue únicamente para:

- calculadora;
- filtros;
- buscador de distribuidores;
- galería;
- componentes interactivos.

No convertiría todo el sitio en Vue.

---

# 33. Por qué no hacer todo en PHP

PHP funcionaría perfectamente en hosting compartido.

Pero para este sitio:

- agrega lógica innecesaria;
- facilita mezclar vista y backend;
- requiere más mantenimiento;
- tiene más superficie de ataque;
- no aporta nada a la mayoría de las páginas.

Lo utilizaría únicamente donde realmente hace falta:

```text
/api/contact.php
/api/budget.php
/api/distributor.php
```

---

# 34. Por qué no elegir Eleventy como primera opción

Eleventy también sería técnicamente válido.

Ventajas:

- muy liviano;
- excelente generación estática;
- simple;
- rápido.

Sin embargo, Astro ofrece para este proyecto:

- mejor experiencia con componentes;
- soporte sencillo de Vue;
- manejo cómodo de assets;
- organización más natural de layouts;
- componentes reutilizables;
- mejor ergonomía para agregar interactividad progresivamente.

## Orden recomendado

1. **Astro**
2. Eleventy
3. PHP tradicional

# 37. Formularios

Para hosting compartido:

```text
Astro frontend
      ↓
POST
      ↓
PHP
      ↓
validación
      ↓
mail / SMTP / WhatsApp API
```

Nunca exponer claves en JavaScript.

El PHP debe:

- validar;
- sanitizar;
- verificar CSRF;
- aplicar rate limit básico;
- usar honeypot;
- opcionalmente Turnstile;
- registrar errores;
- enviar por SMTP.
